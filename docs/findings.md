# In-game findings

Facts verified by running mods in the installed game, where the wiki is wrong, silent or misleading.
They override the wiki. Read this index first, then open only the topic file you need.

Adding a finding: put the entry (`## Title (date)`, evidence: log line, error, session name from `.cache/logs`) in
the matching `docs/findings/<topic>.md` (or a new topic file), and add its line here. Never write the entry itself
into this file.

## Mod scripts, params, stylesheets and Lua limits (`findings/scripting.md`)

- **Mod params, script functions and stylesheets**: a mod.json param can't change a `.css.lua` (6 channels failed): ship variant mods. Param values are 1-based option indices, also for `numbers`.
  - Script function signatures: `runFn(captureParams, settings, allModParams)`; `preRunFn` and `postRunFn` also take `captureParams` first. runFn runs in ~50 Lua states.
  - Stylesheets (`*.css.lua`): own Lua state with only `api.gui`/`api.type`, no `rawget`; a Lua error drops the whole stylesheet. The `loadStyleSheet` modifier never fires.
  - Debugging tips: never remove a staging mod while a save is loaded (assert "cannot remove mods in game"); adding one is fine. Re-run every `subscribeToEvent` once per load: subscriptions are saved.
- **200 locals per function, also in a `.tl` file's main chunk (2026-10-10)**: over 200 top-level locals fails to load ("too many local variables") and can take the whole UI down. Group constants and helpers into tables; `make check` reports it.
- **Translations: `strings.json` and `_()` (research 2026-10-10, in-game checks pending)**: `_()` translates at once in GUI scripts; in resource files it returns the key, so wrap the whole string, never format or compare it. Keys: the 13 locale codes. modinfo localizes only name and summary.
- **Load crash above ~200 mod stylesheet rules (verified in game 2026-10-10)**: total mod CSS rules over ~205 (each comma part counts) crash the first frame after load (`102fbe0cc`). Keep stylesheets small; inline `meta.styleSheet` replaces class rules. Timetables alone has 187 rules (2026-10-12); a crash can also follow a mod switch from a big set in the same game session, at only 48 rules: restart the game first. 400 inert rules alone (no scripts, only mod) crash loading a large save (2026-10-12).
- **Mod description rendering in game (verified in game 2026-10-11)**: the in-game Mod Hub renders `<p>`, `<strong>`, `<h4>`, `<ul>`/`<li>`; `<em>` is ignored, `<hr>` draws no line, whitespace between adjacent tags is dropped. Links show as `text (URL)` and images are dropped (2026-10-13, `findings/publishing.md`).
- **Mod settings tooltips not seen in game (user report 2026-10-11)**: param tooltips may not show in the mod list, so document every param, its options, default and effect in `description.html` "Settings".
- **`api.engine.config.getConfigDict()` returns a list of `{key, value}` pairs (verified in game 2026-10-13)**: not the `{ string : string }` its tealdef says; `dict.climate` is nil. Walk the list (accept both shapes).
- **BaseConfig: set in preRunFn, read-only at runtime (2026-10-12)**: write BaseConfig in `preRunFn` (4th arg); `game.config.<field>` is nil in runFn. `api.res.getBaseConfig()` fields are read-only at runtime from GUI and game scripts alike.
- **`rawget` is nil in GUI script states (2026-10-11)**: GUI and game-script states have no `rawget` (load crash / endless error loop); mod and name scripts do. Use `pcall(function() return _G[k] end)`. Quit the game fully to pick up a fix.
- **In-game Lua is pre-5.3 (crash 2026-10-03)**: no 5.3-only library calls (`math.tointeger`, `math.type`, `utf8.*`, `string.pack`, `table.move`); `//` and bitwise ops are fine in `.tl` (target 5.1), never in plain `.lua`. `make check` lints it.
- **mod.json param `numbers` must be doubles (2026-10-08)**: write `60.0`, not `60`, or the mod is silently skipped ("Failed to parse mod.json" in stdout.txt). `make validate` checks it.
- **runFn: call addModifier every time (2026-10-06)**: never guard `addModifier` with a file-level "registered" flag (the script stays cached, the modifier table doesn't); make the modifier idempotent.
- **Removing a staging mod while a save is loaded crashes (2026-10-09)**: deleting a staging mod, `make unlink` or a branch switch that drops a mod asserts "cannot remove mods in game": the user quits to the main menu first.
- **Animals from a GUI script: spawn and remove yes, move no (user console 2026-10-14; tealdefs)**: `makeAnimalSpawnAtCmd("::/animal/<x>/<x>.mdl", Vec2f, lookAt?)` from the console (a GUI state) spawned a cougar (callback unconfirmed); `makeAnimalSetStateCmd` has no position or target, so existing animals can't be moved; `makeCustomEntityDestroyCmd` removes an animal (campaign game script). See [scripting](findings/scripting.md).
- **The draft horse is a spawnable animal that lives anywhere; the noise probe reads >= 60 dB on open desert (game files + log 2026-10-14_2150)**: `draft_horse.mdl` has `metadata.animal` (density 0, every suitableAreas value 0); cows, sheep and `horse.mdl` don't. Every cougar spot in that session scored "noise 60": the probe's dB scale against the engine's is unconfirmed, so score only to prefer a spot. See [scripting](findings/scripting.md).
- **Added animals die within seconds where their suitableAreas score is negative (game log 2026-10-14_0842_session; cause inferred)**: cougars on 0.45 slopes (negative from ~0.31) were gone in 6-25 s, birds lived; score spots the engine's way (bias, height / noise / slope maps, civilisation / forest / predator / shore / water). `getComponent` on a despawned one raises "Invalid entity"; ids are reused at once. No elk model. See [scripting](findings/scripting.md).

## Game scripts (`findings/game-scripts.md`)

- **Game-script pauses don't stall rendering (2026-10-10)**: a slow game-script `update` costs simulation time, not frames; per-frame GUI work is what players feel. `tickCount` moves per sim step (~200 ms), and `update` can run in several Lua states, so "once per interval" guards may fire twice.
- **Game-script `update` runs in ~11 Lua states with their own module locals (game log 2026-10-20)**: each with its own timers, caches and log lines; the `Sim Pool N` thread name does **not** identify the Lua state (one state's lines came from several threads, two states logged from one), and each state runs `update` in only part of the ticks (a 4-update cycle took ~5 s game time); `state:get` / `set` acted serialized across them for Better Auto Vehicle Renamer (no double sends), but a get / set pair isn't atomic: give shared once-only work one owner (a lease in the state) and expect that owner to run only every few ticks. A state's first `update` can come 84 s game time after another's in the same load: "first update of a load" needs a wall clock or a wide margin, never a reset of shared state.
- **GUI-side `state_native:find` per frame is safe and cheap (game 2026-10-20)**: in `guiUpdate`, `getComponent(GAME_SCRIPT).state_native:find(key)` reads one saved key without asserting (~14 us); copying the state with `state:get()` only when a change number moves halved Organic Towns' tick cost.
- **Game-script `get_native` asserts (2026-10-10)**: `state:get_native()` / `findPath` in a game script triggers fatal `gamescript_util.cpp:385` asserts. Use `state:get()`; the GUI-side `gameScript.state_native` is fine.
- **Mission marker types are a fixed list (verified in game 2026-10-10)**: `setMarkerAt*` types are only `arrow`, `exclamation`, `question`, `question_red`, `locate`; no `exclamation_red`, no colour argument. Only `question_red` is red.
- **guiHandleEvent needs guiUpdateScript and subscribeToEvent (verified in game 2026-10-07)**: register a (no-op) `guiUpdateScript` and call `state:subscribeToEvent(name)` in `update`, or `guiHandleEvent` never fires.

- **No depth of field or blur in env files, api or cutscenes (game files 2026-10-14)**: env blocks are atmosphere / light (exposure, contrast, tone map) / water / shadows / skyBox; the final compose pass reads only the frame and a full-frame bloom blur, no depth; cutscene keyframes carry fovY and ~40 atmosphere fields but no focus. ## Publishing (Mod Hub, mod.io) (`findings/publishing.md`)

- **Mod Hub uploads and the mod.io gallery (2026-10-10)**: name slides `N-<hash>.png` (zero-padded at 10+) so a Hub upload keeps the gallery intact; at most 10 slides (mod.io 13003). Check `make modio ARGS=--diff` after an upload. Update 2026-10-14: a Hub upload left every 10-slide gallery out of order on mod.io (slide 10 second); galleries of 1-8 slides stayed in order, so slides are now capped at 9 (single-digit names); `make modio MOD=... ARGS='--apply --only gallery'` repairs an out-of-order gallery.
- **mod.io description HTML (2026-10-13, mod.io page + frontend; in game untested)**: `<blockquote>` is supported and styled (Pay Your Tolls uses it); `<img>` with `width` (percent works, 24% for four tiles a row) inside `<a>` makes linked tiles from other mods' CDN images (`image.modcdn.io/mods/<md5(id)[:4]>/<id>/<file>`); mod.io's server strips inline `style` on save (verified 2026-10-13), so no margins or rounded corners. In the game's Mod Hub (verified 2026-10-13) images are dropped and links show as `text (URL)` (an image-only link as the bare URL).
- **Server-side validation rejects `api.util.saveAppConfig` (2026-10-20)**: Line Manager Plus and Photo Mode were rejected after upload; store mod data with `api.gui.game.setGuiSaveData(modId, table)` / `getGuiSaveData(modId)` (per savegame, one table per mod), never in `AppConfig.mainMenuState`. `make validate` errors on it (`findings/publishing.md`).
- **Upload validator runs script chunks without `api.engine` (2026-10-20)**: a module-level `pcall(api.engine.x.f)` fails the Hub upload ("attempt to index field 'engine'"); wrap the access in the pcalled function or read at mount (`findings/publishing.md`).
- **Hub uploads don't reliably update the description (game log 2026-10-21, inferred)**: every Hub upload logs one mod.io HTTP 500 a few seconds in; the modfile and gallery go through but the description can stay old, even when the game had re-read the edited `description.html`. Follow every upload with `make modio ARGS='--only text --diff'` / `--apply`. See [publishing](findings/publishing.md).
- **Description length: 50,000 characters (2026-10-16, Hub upload)**: mod.io rejects a longer description with error 13009 (Smart Lanes rev 8 at 57,661 chars); the swagger's 150,000 is not enforced. `make validate` errors above 50,000, warns above 40,000.
