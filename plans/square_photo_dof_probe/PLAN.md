# DoF probe (DEV)

Status: rev 1 built 2026-10-14, not run in game. DEV only: never uploaded, no translations.

Question: can Photo Mode get depth of field (or at least tilt-shift) through a shader, and can it be switched
per look so normal play is untouched?

## What we know (docs/findings/environment.md "Shaders", "What an env file controls", "Haze")

- No DoF anywhere in env files, the api or cutscenes. Haze only grows with distance: it can't fake a focus band.
- A mod most likely can't replace a base shader (resources are namespaced per mod; Realistic Environment Pro has
  players copy its shaders into the install). So any shader effect = a manual install on PC, never on console.
  The mod-folder override itself is still tested by `mods/square_shader_override_probe` (photo quality probe T12).
- The final compose pass has no depth. The `ssr_apply` pass has the lit frame, the depth buffer, a blurred mip
  chain and the `Light` uniform block (with `latitude`): the probe lives there.

## Design

- `shader_files/base/content/rendering/programs/shaders/misc/ssr_apply.fs`: the base file (build 40420, sha256
  `3d5a2ed8…5a5b`) with the base `main` renamed `sqdofBaseMain` and a new `main` appended; every change marked
  `// sqdof:`. After the base work it reads the mode from `u_light.latitude`: mode = floor((lat + pi/2) / 2 pi).
  Base climates (|lat| < pi/2) give 0 = untouched picture. Modes: 1 tilt-shift (sharp band +-10 % of the
  screen height around the middle, full blur from +-38 %), 2 DoF focused on the nearest of 5 depth samples at the
  screen centre (sharp within +-25 % of the focus distance, near side blurs twice as fast), 3 shallow (+-8 %),
  4 debug (left half: the blur source; right: depth, white = near; green centre line). Blur = `blurredTex` at
  lod = strength x min(maxNumMips, 5); if `maxNumMips < 1`, a 13-tap disc on the sharp frame. A 6 px magenta
  square in a screen corner is always drawn (install marker). `#define SQDOF_FORCE_MODE` overrides the channel.
- Channel: `light.latitude + 2 pi * mode` in an env file. Chosen because the post pass can't see the live
  atmosphere fields, and REP already uses cloudBase / cloudTop / cloudScattering / dayOfYear (which Photo Mode
  also writes). Latitude feeds the sky's star rotation (a rotation, periodic) and, presumably, the CPU sun path
  (assumed periodic, check in T2). Not live: switching = an env switch (Photo Mode already switches env per look,
  so a look could carry a mode).
- Mod: `content/environments/sqdof_<climate>_<mode>.env.lua` (4 climates x 4 modes, generated by `gen_envs.py`
  from the base env files: only latitude, name, isToolEnvironment, absolute texture names change) and a top-bar
  button (`content/sqdof/sqdof_gui.script.lua`) that cycles off -> tilt -> dof -> dof_shallow -> debug -> off,
  carrying the six live atmosphere values, switching back on Off / the pause menu / unmount. Rendering only.
- `shader_install.sh status|install|restore`: copies the probe file over the game's, keeps the original in
  `.cache/sqdof_backup/`, refuses an unknown base (game update, REP), deletes the cached `ssr_apply` SPIR-V.

## Open / next

- Run TESTING.md T1-T5. Results decide: does the pass run with Reflections off (if not, Photo Mode DoF needs
  Reflections on or a compose.fs variant with tilt-shift only), does latitude reach the shader unchanged, does
  the sun stay put, how the blur looks (mip chain quality, edge halos), cost.
- If it works: Photo Mode could ship an optional "DoF shader (PC, manual install)" note plus look files with a
  mode; never automatic. Conflicts: REP replaces other files (check whether it ships `ssr_apply.fs`; if so the
  two can't be combined without a merge).
- After a game update: `shader_install.sh status` (sha check), compare the new base `ssr_apply.fs` with the
  probe's base part, re-run `uv run plans/square_photo_dof_probe/gen_envs.py --check`.
