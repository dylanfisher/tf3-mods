# Industry Flows (`square_industry_flows`): plan

Search for an industry type (e.g. "fish") and see the base game's 3D cargo-flow arrows for **every** industry of that type at once: the same arrows the industry window draws for one selected industry.

**Status (2026-10-06):** phase 1 (spike + skeleton) built and **verified in game** (arrows render for every industry of the hard-coded type; log: `'fishing_grounds': 4 industries, 32 links (0 active), 32 drawn`). Phase 2 (pure model) built. Phase 3 (full panel) built: search field, type list with counts and multi-select, Outputs / Inputs / Potential toggles, summary line, HUD icons kept; `make check`, `make test` (40 tests) and `make validate` (2 warnings left for phase 4: authors, cover image) pass. **Awaiting the phase 3 in-game test** (`TESTING.md`). Phase 4 not started.

## Decisions (2026-10-06)

| Topic | Decision |
|---|---|
| Entry point | Button in `::MainModButtonAreaExtension` (as in `square_problem_radar`) that opens a panel styled like a layer legend. A real map layer isn't possible: the layer ridge's button list is hard-coded (`base/content/gui/layers/layers_button_ridge.tl:330-430`), with no extension point. |
| Filter by | Industry **type** (construction file / display name). The search box matches type names and the names of the cargos a type consumes or produces ("fuel" finds the oil refinery). The list shows matching types with their input > output cargo icons and how many are on the map. Select one or more. |
| Arrows | Toggles for **Outputs** (industry → consumers incl. towns), **Inputs** (suppliers → industry) and **Potential** (links with no cargo moving yet: faded and still, like the base window). |
| Lifetime | Arrows show while the panel is open and clear when it closes. |
| Saves | Read-only, GUI-only if possible (no game script, no state). Cosmetic, severity None/None. See the memory "Don't impact existing saves". |

## How the base game does it (research)

- Arrows: `api.type.LayerConfig.CargoFlowRenderableConfig` with `flowData : {FlowData}` (`from`, `to`, `speed`, `arrowColors`, `cargoIconAlpha`, `cargoTypes`). Definition in `.cache/game/api/tealdef/api/type.d.tl:4875-4895`.
- Built in `base/content/gui/entity_window/industry/industry.tl:195-260` (data) and `:329-361` (FlowData):
  - `industry_util.forEachMatchingStocklist(stockList, StockListType.InputStock|OutputStock, fn(otherIndustry, cargoType))`
  - `town_util.forEachMatchingStocklist(stockList, fn(town, cargoType))` for town consumers
  - `cargo_util.getCargoFlowCount(from, to, cargoType, isTown)`: > 0 = actual flow
  - position = bbox top centre from `BOUNDING_VOLUME`
  - colours `layerColors.CargoFlow.Suppliers3D/Consumers3D.{Actual,Potential}` from `::/gui/layers/layer_colors.gres`; potential colours use `color_util.toArray4WithTransparency(..., transparency.VeryLow)`; speed 40 / 0; icon alpha 1.0 / 0.6
- Applied with `builtin.LayerConfig{ config = layerConfig }` as a child of the `builtin.ActionDescriptor` that the window returns through `params.setActionFn(...)` (industry.tl:363-410; also `subventions_gui.tl:438-472`).

## How a mod panel makes a LayerConfig take effect (answered in phase 1)

**Answer: register the panel as a tool and push it onto the game's default tool stack.** Its window content calls `payload.setActionFn(fn, key)`; `fn` returns a `builtin.ActionDescriptor` whose children include `builtin.LayerConfig{config = ...}`. Implemented in `content/industry_flows/gui/flows_window.script.tl`.

Evidence (all under `.cache/game/base/`):

- A `LayerConfig` only renders as a child of the **active action**. There is no `api.gui.*` call that pushes a layer config: every `builtin.LayerConfig` in the base GUI sits inside an `ActionDescriptor` returned through `setActionFn` (`rg builtin.LayerConfig content/gui`: industry, town, station, vehicle, statistics, every layer, subsidy, construction). `builtin.LayerConfig` / `ActionDescriptor` are plain userdata builtins (`content/gui/main/builtin.lua:176, :231`; params `tealdef/scripts/builtin.d.tl:1338-1382, :1484`).
- `setActionFn` comes from the **ToolStack**: each entry is a `ToolStackEntryWrap` that binds its action to the renderer component with `react.useAction` and becomes the active owner when it is on top (`content/gui/main/builtin.lua:1162-1194`, `updateTop` :1240-1248, `push` :1339-1353 / API :1383-1390, `pop` clears the action :1287-1305). Only the **top** tool's action is live.
- Mods can reach the stack: `game_react_globals.getDefaultToolStack()` / `getDefaultToolStackApi()` / `getDefaultWindowContainer()` / `getDefaultRendererComponent()` (`content/gui/main/game_react_globals.tl:9-28`, backed by `game.tl:597-610`). Official mods already use this module (`mods/release/urbangames_campaign_mission_05/.../perk_icons_replacement.script.tl:4`), though none of them pushes a tool (no mod precedent for that part).
- Base pattern for a plain window as a tool: `tool_react_util.registerToolWithWindow(name, windowId, WindowRecipe)` (`content/gui/main/tool_react_util.tl:12-85`); used by Music Player (`gui/music_player/music_player.tl:285`, pushed from `game_bar.tl:154` with `{gameCtx = gameCtx}`), Company, Finances, Notification log, Calendar editor. Statistics is the same with an action (`statistics/statistics.tl:279-467`, pushed at :692). The window gets `payload.setActionFn` and `onClose = ctx.popSelf` (`tool_react_util.tl:12-27`).
- `react.useAction` exists but is marked "for internal use only" (`tealdef/scripts/react.d.tl:372`), so it is not used. `preferredLayerConfig` (`game.tl:129-133`) only feeds the construction menu (`construction_react_util.tl:1370`), so it is no route either. `MainModButtonAreaExtension` plugins get no `gameCtx` (`main_mod_button_area.tl:13`), so the mod builds the three fields the tool needs (`rendererComponent`, `windowContainer`, `toolStack`) from `game_react_globals`.

Consequences (design changes):

- Arrows render **only while our tool is on top**. Opening Statistics/Finances (push without stacking) clears the stack and closes the panel; our own push (no stacking, like Statistics) closes entity windows and other tools.
- The action uses `selector_react_util.makeDefaultSelector(rc, ref, allowStacking = true)` like the layers (`layer_cargo_flow.tl:345`): clicking an entity stacks its window on top, our window is shelved (hidden by id, `tool_react_util.tl:61-71`) and our arrows give way to that window's; closing it brings both back.
- Phase 1 left out `HudIconManagerConfig`, so the usual HUD icons may vanish while the panel is open. Phase 3 adds it (see "Panel").
- Arrow data: one pass over all `INDUSTRY` entities per poll (counterpart lists by cargo), then the same links as `industry_util.forEachMatchingStocklist` / `town_util.forEachMatchingStocklist` for each selected industry, deduplicated, sorted, active first, capped at 400 (`flows_gather.tl`). Industry type = `CONSTRUCTION.fileName` of `getConstructionEntityForSubconstruction(industryEntity)` (`hud_icon_toolbox.tl:242-245`); phase 1 matched a plain substring (`"fishing_grounds"`) and logged every fileName once. Confirmed in game: keys look like `::/industries/fishing_grounds/fishing_grounds.con`, `::/industries/farm/farm.con`, `::/industries/oil_platform/oil_platform.con` (one per construction file), so phase 2 selects **exact** keys.

## Model (phase 2, built)

Split: `flows_gather.tl` only reads the engine into plain records; `flows_model.tl` is pure (no `api.*`, no base modules) and unit-tested (`tests/square_industry_flows/test_model.lua`). Records live in `content/industry_flows/industry_flows_types.d.tl` (byte-identical editor copy in `tealdef/industry_flows/`; types come in via `tealdef/square_industry_flows_def.d.tl`, never `require`d from code).

- Gather: `typeOf(entity)`, `typeName(key)` (cached), `readWorld() : IndustryFlowsWorld` (`industries` with typeKey, position, sorted cargo lists for rule inputs/outputs and Input/OutputStocks; `towns` with position and flattened `cargoNeeds`; `typeNames` key → localized name), `flowCount` (= `cargo_util.getCargoFlowCount`). (The GUI calls `readWorld` and `model.buildView` separately so selection / toggle changes reuse the last read.)
- Model: `MAX_LINKS = 400`; `prettifyKey(key)`; `displayName(key, localizedName)`; `groupTypes(world)` (by key, `""` skipped, count + sorted entities, sorted by name case-insensitively then key); `search(types, query)` (trimmed, case-insensitive plain substring over name, key **and** input / output cargo names from `world.cargoNames`, empty = all, sorted by name); types also carry `inputs` / `outputs` (union over their industries) and `cargoNames`; `newSelection(keys?)`, `toggleSelected(sel, key)` (returns a new set), `selectedKeys(sel)` (sorted); `defaultToggles()` (all on); `buildView(world, selection, toggles, flowCount) : IndustryFlowsView`.
- `buildView` rules: industries and towns iterated in entity order, cargos sorted, so the result never depends on engine iteration order. Inputs = every industry with an OutputStock of a cargo a selected industry consumes; Outputs = every industry with an InputStock of a produced cargo, plus per town its first need the industry produces. Self links and links without both positions are dropped (flowCount is only asked for drawable links). De-dup on (from, to, cargo): the first one wins (a selected industry's inputs come before its outputs). `flowCount > 0` = active; Potential off drops the rest. Sort: active first, then fromEntity, toEntity, cargo (a total order). `total`/`active` count all kept links, `links` holds at most `MAX_LINKS`, `drawn = #links`. Positions are copied, so the view shares no tables with the world.
- `IndustryFlowsView` changed: `typeKeys : {string}` (was `typeKey`), new `drawn`.

### Display name of an industry type

Source: the construction resource's `description.name`, looked up from `CONSTRUCTION.fileName` with `api.res.constructionRep.find(fileName)` + `get(id)` (the base pattern for a fileName: `.cache/game/base/content/gui/construction/construction.tl:1236-1240`; `findAndGet` errors on a missing resource, `api/tealdef/api/res.d.tl:30-33`). It is already localized: the `.con` sets `name = _("INDUSTRIES_FISHING_GROUNDS_NAME")` in `data()` (`base/content/industries/fishing_grounds/fishing_grounds.con.lua:5-6`), and the base game shows `conData.description.name` to players without another `_()` (`game_mechanics/notifications/availability_notifications.script.tl:69` → `notifications/types/con_availability.script.tl:44-45`; construction menu `gui/construction/construction_react_util.tl:979`). The industry window title and the statistics industry list show the **instance** name (`api.engine.util.getEntityName`, `gui/entity_window/make_entity_window.tl:137`, `gui/statistics/statistic_industries.tl:355-357`), e.g. a town-prefixed name, so they are not type names. Fallback (`model.displayName`): empty, missing or raw-id names (`^[A-Z0-9_]+$` with an underscore) become the prettified file name, e.g. `Fishing Grounds`. To confirm in game: the once-per-session log now prints `name = key xN` for every type.

## Panel (phase 3, built)

Top to bottom (`content/industry_flows/gui/flows_window.script.tl`, styles in `flows_window.css.lua`, window content 340 px wide):

1. **Search field**: `builtin.TextInputField{ value, placeholderText, onTyping, onValueChange }` (`.cache/game/base/tealdef/scripts/builtin.d.tl:935-956`). Base search fields use exactly this shape: statistics `statistics/statistics_react_util.tl:167-183` (`placeholderText = _("Search...")`, `value`, `onTyping` and `onValueChange` both set the filter), mod manager `menu/mod_manager_react_util.tl:1110-1116`, savegames `menu/savegame_react_util.tl:705-711`. `onTyping` fires per keystroke, so the list filters live. Typing only re-runs `model.typeList` over the types of the last poll; it never reads the map.
2. **Type list**: header "Industry types (n selected)" plus a **Clear** button (`builtin.Button`) when something is selected; one row per matching type = `builtin.CheckBox{ value, onValueChange, label = name }` + cargo icons (inputs, chevron, outputs; `cargo_react_util.makeCargoIcon` like `statistics/statistic_industries.tl:97`) + count `TextView` at the right. Controlled checkbox (value + onValueChange) as `builtin.d.tl:1022-1031` recommends and `menu/mod_selector_page.tl:443-448` does; `label` makes a click on the name toggle too. Multi-select; selected types stay selected when the search hides them ("+n selected, not in this list"). More than 8 rows: the list sits in a `builtin.ScrollArea` (`builtin.d.tl:749-758`, policies AlwaysOff / AsNeeded) whose content is a `builtin.Component{ layout = ... }` (a layout directly throws "ScrollArea does not accept a Layout as content") of fixed height 220 px (CSS, sized like `main/menu_category_util.css.lua:23-26`). The ScrollArea is a builtin directly in a BoxLayout, which is fine; the content recipe itself still returns a BoxLayout (memory "Recipe must return layout").
3. **Toggles**: three labelled `builtin.CheckBox`es (Outputs, Inputs, Potential links), base shape `line_vehicle_mgmt/cargofilter_window.tl:755-764`, `layers/layer_react_util.tl:68-74`. All on by default. The collapsible list (`main/collapsible_checkbox_list.tl`) was not used: it is a `List` with gamepad selection logic and collapse state, too heavy for three toggles and a filtered list.
4. **Summary**: `model.summary(view, selection)` → "{n} industries · {links} links · {active} active", plus "Showing {drawn} of {total} (active first)" when capped. Nothing selected: "Select an industry type to show its cargo flows." None on the map: "None of the selected types on the map."
5. **Legend**: the phase 1 hint about moving vs faded arrows.

Behaviour:

- Starts with nothing selected (no arrows). Search text, selection and toggles live in a module-level `session` table (`IndustryFlowsPanelState`) in the window script: reopening the panel restores them for the rest of the session. Nothing goes to the savegame or game script state.
- Data: one `gather.readWorld()` per 2 s poll (`react.onStepTimer`, same pattern as `engine_react_util.useStepStateTimer`, `engine_react_util.tl:128-149`, with `table_util.deepEquals` to skip unchanged polls). The poll reads the current choice from `session`, never a captured one. The last read is kept (`lastWorld`): a selection or toggle change rebuilds the view from it at once (`model.buildView` + `cargo_util.getCargoFlowCount`), without re-reading the map.
- Pure helpers (unit-tested): `model.withToggle`, `newPanelState`, `copyPanelState`, `typeList(types, query, selection)` → rows (key, name, count, selected) + `selectedCount` + `hiddenSelected`, `summary(view, selection)` → state `empty` / `loading` / `none` / `links` + counts + `capped`. Records in `industry_flows_types.d.tl`.
- **Performance (2026-10-07)**: no poll while the window is shelved (`api.gui.byId.isVisible(WINDOW_ID)`, the flag `tool_react_util` shelving sets); types and view are compared apart and an unchanged part keeps its table, so the cached LayerConfig survives a types-only change; the action function is cached (`LayerCache`) and only replaced when the view, the HUD filter or the renderer changes, because a new function re-binds the whole action (`builtin.lua:1165-1175`, `react.lua:611-614`); cargo icon paths / tooltips cached per cargo. Not adopted: caching typeKey / position per entity (ids can be reused and `getRevision` has no documented semantics), capping before `flowCount` (would change total / active), a slower world read (delays new industries).
- **HUD icons**: the action now has a `builtin.HudIconManagerConfig` built like the base default action (`main/selector_react_util.tl:324-345`, `makeDefaultSelectorAction`; e.g. used with a LayerConfig by the warehouse window, `entity_window/warehouse/warehouse.tl:96`): `masterRecipe = hud_icon_toolbox.HudIconMasterGame`, the player's HUD filter re-done from the local `makePreFilter` (`selector_react_util.tl:43-86`, reads `api.gui.game.getGuiSaveData("").hudFilter`, read-only; our copy never mutates it), default visibility thresholds and vehicle icon offsets, costs / income as the filter says. `makeDefaultSelectorAction` itself is not used because its selector does not stack entity windows on top of our tool (`allowStacking = nil`, `selector_react_util.tl:108`). No `accessNotificationCacheFn` (the plugin gets no `gameCtx`), so notification icons on the HUD are skipped (`hud_icon_toolbox.tl:359`); labels are not affected.

## Phases

1. **Spike + skeleton.** *(built, awaiting in-game test)* Scaffold the mod (`make new-mod`). Answer the open question above. Ridge button → panel. Hard-code one industry type and prove the arrows render for all of its instances. Write down which mount works and why.
2. **Model (pure, unit-tested).** *(built, see "Model")* `flows_model.tl` (move the link building out of `flows_gather.tl`, which then only reads the engine): type search/match, grouping industries by type, building flow records (from/to/cargo/actual) from plain inputs, applying the Inputs/Outputs/Potential toggles, a cap on the arrow count and de-duplication. Tests in `tests/square_industry_flows/`.
3. **Full panel.** *(built, see "Panel"; awaiting in-game test)* Search box, matching type list with counts and multi-select, the three toggles, a summary line ("12 industries · 48 links · 31 active"). Refresh flow data on a slow timer (actual vs potential changes over time), not every frame.
4. **Polish + review.** Localisation-ready strings, `make check`, `make test`, `make validate`, the in-game checklist `TESTING.md`, and modinfo text.
